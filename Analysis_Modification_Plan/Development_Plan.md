# ArcMeta 项目开发规约与演进计划 —— Development_Plan.md

## 1. 托管库 (ArcMeta.Library_) 自动化链路规约

### 1.1 实时监控与登记 (ReadDirectoryChangesW)
- **触发机制**：利用 Windows 原生 `ReadDirectoryChangesW` 接口（由 `NativeFolderWatcher` 驱动）实时监听 `ArcMeta.Library_[盘符]` 文件夹的物理变动。
- **身份登记 (Status 0)**：
    - 监听到变动后，系统应立即调用注册函数。
    - 将项目的 **File_ID** 与**传统物理路径**写入 `metadata` 表。
    - 物理标记 `ingestion_status`（标记值）初始化为 **0**。
- **解析与完工 (Status 1)**：
    - 登记完成后，调用 `ImportHelper.cpp` 作为统一解析引擎，处理所有标记为 **0** 的项目。
    - **状态更新**：解析任务（颜色、属性等）彻底完成后，将数据库标记值从 **0 更新为 1**。

## 2. 手动干预与精准同步规约

### 2.1 右键菜单交互逻辑
- **对象范围**：凡是物理路径位于 `ArcMeta.Library_` 文件夹内的项目。
- **“重新扫描”显示规则**：
    - **强制呈现**：无论该项目是否已经入库（即不论标记值是 0、1 还是未入库状态），右键菜单中必须**始终显示“重新扫描”**选项。
- **核心原则：作用域可控**。
- **执行范围**：严格锁定为 UI 界面中**“被选中”**的项目（文件或文件夹子树）。
- **行为定义**：
    - 强制执行物理状态同步与元数据重新解析。
    - **全量扫描定义**：盘符栏下的“重新扫描该盘”是指扫描该盘符下的“ArcMeta.Library_[盘符]”文件夹里所有的数据（对应用户原话：““重新扫描该盘” 应该是扫描该盘符下的“ArcMeta.Library_[盘符]”文件夹里所有的数据”）。
    - **状态无关性**：无论被选中项（或全量文件夹）当前的标记值是 0 还是 1，系统必须**无视现有状态**，强制执行重新解析流程。
- **严禁扩权**：禁止越过“被选中”蓝框去触碰任何非选中区域的数据。

### 2.2 拖拽入库冲突拦截
- **触发场景**：用户将位于 `ArcMeta.Library_` 路径下的项目拖拽至侧边栏分类。
- **拦截逻辑**：
    - **已入库判定**：若该项目已经入库（标记值为 1），必须立即阻断操作。
    - **交互反馈**：弹出显式警告提示：**“该项目已入库，无需再次入库”**。
- **执行逻辑**：只有在未入库的情况下，才允许执行重新扫描并入库的操作。

## 3. 视觉反馈与性能加固规约 (进度弧线)

### 3.1 进度弧线驱动逻辑
- **标记驱动而非扫描驱动**：进度弧线（百分比圆圈）必须完全通过数据库中的 **0 (待解析)** 和 **1 (已完成)** 标记值计算得出。
- **严禁实时物理统计**：计算进度时，禁止调用任何物理读盘函数（如 `QDirIterator`）。
- **公式**：`进度 = (该目录下状态为 1 的项目数) / (该目录下状态为 0 和 1 的项目总数)`。

### 3.2 数据库持久化与加载
- **物理落地**：文件夹的进度百分比必须记录到数据库的专属字段中。
- **启动零开销**：下次启动主程序时，UI 直接从数据库加载已存的进度数值进行渲染。严禁在启动阶段反反复复进行聚合计算。

### 3.3 逻辑收拢：专属原子函数
- **职责唯一性**：必须建立专属函数负责标记值的更新与比例值的同步。
- **数据一致性**：确保每一笔 0 到 1 的翻转均由该专属函数原子化完成，并同步更新父目录的持久化进度值。

### 3.4 进度弧线作用域限定
- **严格限定范围**：进度弧线仅作用于物理路径位于
  `ArcMeta.Library_[盘符]` 文件夹内的项目。
- **Library外项目**：一律不渲染进度弧线，不查询
  `ingestion_status`字段，不做任何统计计算。
- **判断方式**：通过路径前缀匹配判定，与`AutoImportManager::
  getManagedLibraryPath`使用同一套判定逻辑，确保全系统一致性。

## 4. 架构红线与禁令

- **严禁重复造轮子**：全应用禁止出现两套平行的扫描入库引擎。`AutoImportManager` 仅作为变动监听的触发器，具体的解析逻辑必须收拢至 `ImportHelper`（或归一化后的摄取模块）。
- **严禁启动自扫描**：主程序启动时严禁自动执行全量物理递归。一切物理读盘开销必须由“ReadDirectoryChangesW 实时信号”或“用户手动选中”驱动，以确保 UI 绝对流畅，不发生假死与卡顿。

## 5. 盘符栏逻辑架构规约 (2026-07-xx)

### 5.1 解析状态视觉联动
- **表现定义**：在执行解析任务（颜色、尺寸提取）的过程中，对应的盘符按钮状态应从“打勾”切换为“转圈”（Running 状态）。
- **同步机制**：解析引擎（ImportHelper 或其对应的后台线程）开始工作时通知 UI 状态翻转。

### 5.2 未初始化盘符访问拦截
- **触发场景**：用户左键点击尚未创建 `ArcMeta.Library_[盘符]` 文件夹的盘符按钮。
- **行为定义**：拦截路径跳转操作。
- **反馈定义**：弹出 ToolTip 提示：“尚未创建文件夹，请单击右键进行创建托管文件夹”。

## 6. 数据库实时同步与秒退出架构规约 (2026-07-xx)

### 6.1 实时同步架构 (内存优先)
- **核心逻辑**：严格执行“启动时：磁盘同步到内存；运行期：内存同步到磁盘”架构。
- **启动期同步**：程序初始化时，必须通过 `sqlite3_backup` 将磁盘数据库全量加载到高速 `:memory:` 库中。
- **运行期同步**：任何元数据变更（如评分、标签、备注等）必须遵循“先更新内存库，成功后再异步、增量同步到物理磁盘数据库”的顺序。
- **内存优先规约**：确保 UI 响应由内存库驱动，杜绝因磁盘 I/O 导致的界面卡顿。

### 6.2 秒退出机制
- **秒退出规则**：退出程序时严禁执行任何全量备份或耗时的同步逻辑，必须实现秒退出。
- **彻底移除退出同步**：由于运行期已实现实时增量同步，退出时彻底移除 `flushStep` 备份循环以及相关的进度条 UI（如用户截图所示）。

## 7. 顶层 UI 容器职责架构规约 (2026-07-xx)

### 7.1 MainWindow 职责审计与去重
- **核心目标**：解决 MainWindow.cpp 职责过载问题，消除“上帝对象”隐患。
- **违规职责识别点**：
    - **硬件消息处理**：如 `WM_DEVICECHANGE` 捕获（应剥离至专职 Service 或 Controller）。
    - **物理磁盘 IO**：如 `mkpath`、物理文件探测（应由专职 Service 处理）。
    - **业务数据持久化**：如直接操作 `CategoryRepo` 或 `MetadataManager` 进行入库（UI 仅应触发动作，不应包含业务逻辑闭环）。
    - **复杂状态机管理**：不属于顶层窗口布局的业务状态机应下沉。
- **MainWindow 唯一职责**：作为顶层 UI 容器，负责面板布局协调、顶层窗口行为控制及 UI 信号转发。
