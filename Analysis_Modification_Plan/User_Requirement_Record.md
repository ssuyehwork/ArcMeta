# 用户需求记录 User_Requirement_Record.md

## 2026-07-xx 架构演进：磁盘优先数据流向与导航引擎自动切换规划

### 1. 需求背景
- 当前程序退出时存在明显延迟，原因是系统采用“内存数据库 + 退出时同步磁盘”的架构。
- 在“目录导航”模式下，进入托管库大目录加载缓慢，因为默认走物理磁盘扫描。

### 2. 用户原话
- “当前版本，我期望先将数据插入到数据库然后更新内存，凡是与此不符的都必须做调整，这样在退出的时候就可以秒推出了”
- “我期望，当从物理磁盘进入到ArcMeta.Library_[盘符]文件夹之后，应该自动切换到内存，因为ArcMeta.Library_[盘符]文件夹里的所有数据都已经在数据库里了，自动切换成内存模式情况下，效率会更好”
- “只要进入到了已入库的文件夹，那么就立即切换到内存模式，这样的话效率就会提高”

### 3. 核心目标
- **磁盘优先（Disk-First）**：由“内存优先”转为“物理磁盘库优先”，开启 WAL 模式，确保实时落盘。
- **秒退出**：彻底移除退出时的同步循环逻辑（flushStep）。
- **导航引擎自动切换**：只要进入已入库（Status 1）的文件夹，立即自动切换为“内存镜像加载”，绕过物理扫盘以提高效率。

### 4. 涉及模块
- `DatabaseManager`: 废弃内存库中转，直接连接物理文件，启用 WAL。
- `MetadataManager`: 重构持久化原子顺序（写库 -> 刷内存），提供入库状态判定接口。
- `ContentPanel`: 重构 `loadDirectory` 加载流程，引入状态驱动的引擎切换逻辑。
- `TrayController`: 裁剪退出逻辑。
