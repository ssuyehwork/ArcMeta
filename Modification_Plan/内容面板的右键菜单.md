### 二、 哪些选项必须判断数据来源（`dataSourceType()`）并执行不同逻辑？

在上述 25 个选项中，有 **7 个核心功能必须根据数据来源（托管库模式 vs 磁盘模式）做严格的逻辑分流**，否则就会导致数据库污染或物理文件误删：

---

#### 1. 设定颜色标签 (ColorStripPicker) ── 🚨 必须判断！
* **托管库模式**：写入 SQLite 数据库 `metadata` 表；
* **磁盘模式**：写入 `.Arcmeta.json` 离散文件（`AmMetaJson`），**绝对不写入 SQLite**。

#### 2. 单项重命名 (`ActionRename` / 行内编辑) ── 🚨 必须判断！
* **托管库模式**：**纯逻辑重命名**。仅改 SQLite 表里的 `name` 字段，物理 `.arc` 容器名与源文件名 100% 不变（0 开销、不上锁）；
* **磁盘模式**：**物理文件重命名**。调用 Windows `ShellHelper::renameItem` 对硬盘文件重命名，并同步更新 `.Arcmeta.json` 里的条目 Key。

#### 3. 批量重命名 (`ActionBatchRename`) ── 🚨 必须判断！
* **托管库模式**：批量修改 SQLite 表里的 `name` 字段；
* **磁盘模式**：批量执行真实物理重命名，并同步更新 `.Arcmeta.json`。

#### 4. 删除 (`ActionDelete` 移入回收站 / `ActionSecureDelete` 永久删除) ── 🚨 必须判断！
* **托管库模式**：从 SQLite 移除关联或将 `is_trash = 1`；
* **磁盘模式**：调用系统回收站 (`moveToTrash`) 或 `SecureFileEraser` 物理抹除，并删除 `.Arcmeta.json` 中的该条目。

#### 5. 归类到 (`ActionCategorize`) vs 迁移 (`ActionAddToCategory`) ── 🚨 必须判断！
* **托管库模式**：显示“归类到...”，修改 SQLite 的 `category_items` 绑定关系；
* **磁盘模式**：显示“迁移”，调用 `AssetImporter::importAssets` 执行 `.arc` 资产包封装入库。

#### 6. 粘贴 (`ActionPaste` / 拖放) ── 🚨 必须判断！
* **托管库模式**：调用 `AssetImporter` 执行打包与元数据入库；
* **磁盘模式**：执行标准的 Windows 操作系统级物理文件复制/粘贴到当前目录 `m_currentPath`。

#### 7. 刷新 (`ActionRefresh` / `refreshAll`) ── 🚨 必须判断！
* **托管库/系统视图**：调用 `loadCategory()` 或 `loadPaths()` 重新查库；
* **磁盘模式**：调用 `loadDirectory()` 重新扫描物理磁盘并加载 `.Arcmeta.json`。

---

### 💡 无需分流的纯通用选项（双模式完全一致）
像 `打开`、`用默认程序打开`、`在资源管理器中显示`、`复制路径`、`添加至收藏夹`、`排序`、`布局显示` 这些选项，无论在什么模式下，逻辑都是 100% 相同的，不需要做模式分流。
