# 2. 关于“内容面板”显示数据的逻辑
## 2.1 内存模式（侧边栏分类）模式下，显示的逻辑应该是这样的（穿透）
例如，卡片里显示的缩略图应该是“1823760_thumbnail.png”，而卡片下方显示的名称应该是“1823760.psd”，不该显示“00mscw74m6001.arc”，卡片左上角也不该显示“DIR”，应该显示“psd”
G:\ArcMeta.Library_G\00mscw74m6001.arc\1823760.psd
G:\ArcMeta.Library_G\00mscw74m6001.arc\1823760_thumbnail.png

## 2.2 磁盘目录导航模式下，显示的逻辑应该是这样的（不穿透）
就是纯粹的目录导航，行为等同于 Windows 资源管理器 / Adobe Bridge。用户从地址栏或目录树打开任何路径，看到的就是这个路径下物理磁盘上原原本本的内容，不做任何解释、不做任何特殊语义翻译。哪怕打开的是 ArcMeta.Library_[盘符] 这个托管库根目录本身，看到的也就是里面原本的文件夹结构（包括所有 .arc 容器），跟打开任何一个普通文件夹没有区别。

## 2.3 慢速多媒体提图与异步闭锁保护机制
为了杜绝慢速资产（如 .ai 格式等）由于反复重绘、选中切换或快速滚动导致后台多媒体提取任务无限重复分发、线程池与 CPU 爆满并引发 UI 假死，所有模型（包括“SQLite 内存模式” `LibraryAssetModel` 与“磁盘目录模式” `DiskItemModel`）必须在 `loadThumbnailsForRows` 中启用严格的防抖上锁机制。在发起 `QtConcurrent::run` 异步提取前，必须将路径记入请求拦截集（如 `m_requestedIcons` / `m_requestedPaths`），在任务完成、写回缓存并通知 UI 刷新后再行移除。任何已被锁定在加载中的路径，后续检索一律 0 毫秒拦截、禁止重复投递。
此外，在 `MediaColorExtractor::getImageForAnalysis` 提取与分析入口处，必须优先检测文件是否位于受控库的 `.arc` 胶囊容器内；若是，则 0 毫秒直接读取同级已落盘的 `_thumbnail.png` 缩略图并返回，绝对禁止重新唤醒 Ghostscript 或 PDF 引擎，从架构源头上彻底掐灭重复提图的性能损耗。

# 3. 关于“侧边栏分类安全加锁与解锁”
## 3.1 物理级数据瞬间隐藏
当侧边栏分类被加锁（包含设置新密码、修改密码、立即锁定）时，内容面板必须通过清除底层模型数据机制（`m_model->clear()`），确保原展示的数据立马隐藏，不可显示出来。

## 3.2 卡片式内置无边框解锁视图
对未解锁的加密分类，移除阻断性模态解锁对话框，统一采用嵌入在内容面板中央的卡片式内置无边框解锁视图（`CategoryLockWidget`），提供输入密码验证功能。解锁成功后，自动通知侧边栏更新解锁图标并切换回常规数据视图。

## 3.3 密码保护子菜单功能项
侧边栏分类右键菜单“密码保护”包含：
- “设置”（未加密状态下可用）
- “修改”（已加密状态下可用，须先验证旧密码）
- “清除密码”（已加密状态下可用，须先验证旧密码）
- “立即锁定”（已加密且当前已解锁状态下可用）

# 4. 关于“空状态占位提示”
## 4.1 空白状态下的友好提示
- [ ] 侧边栏托管分类为空，或者物理双击进入空物理文件夹时，内容面板正中央需通过优雅、低对比度的温和灰字（#888888）绘制显示“没有可显示的项目”。

## 4.2 列表视图组件的职责解耦
列表视图模式下的空文本提示由单独 the `DropTreeView::setEmptyHint` 接口配置。该机制通过接口参数控制绘制，不污染侧边栏自身所共用的 `DropTreeView` 实例，实现职责单一。

# 5. 关于离散元数据标记文件
## 5.1 彻底清退
全工程中彻底清退并清空关于旧版 `.am_meta.json` 的代码、字符串与注释，确保没有任何历史残留痕迹。

## 5.2 标准配置文件名
全局统一使用标准的 `.ArcMeta.json` 作为唯一的隐藏物理配置文件名。该隐藏文件直接保存在对应的物理文件夹内，用以记录资产的离散元数据（星级、颜色、备注、标签等）。

## 5.3 磁盘模式下的打标与过滤支持
为了保证极致的一致性体验，元数据面板与筛选器面板（包括星级、颜色、备注、链接、图像比例等过滤分组）在磁盘目录模式下同样完全启用并显示。同时，磁盘模式下的内容面板右键菜单也会呈现‘设定颜色标签’快捷色块栏与置顶控制，让用户能够直接在物理目录模式下对资产进行离散打标与筛选。

# 6. 关于空托管容器物理与数据一键清除及反向深度清理机制
## 6.1 手动空包对账与物理级联删除机制
在分类面板标题栏右侧，提供一键“扫描并清理空白托管包”操作按钮（标识为 sync 图标，按钮配色和悬停微动与系统其他标题栏按钮对齐）。
用户手动点击该按钮后，系统将在后台全量遍历当前系统中已挂载的所有物理资源库盘符下的 `.arc` 资产文件夹。
若判定某 `.arc` 资产包在物理上为空（无除 `_thumbnail.png` 缩略图和 `.ArcMeta.json` 隐藏配置文件之外的任何真实物理素材），则执行以下物理与数据库的双重彻底销毁：
1. **磁盘级物理擦除**：通过 `QDir::removeRecursively()` 彻底销毁该 `.arc` 物理文件夹；
2. **数据库级元数据级联抹除**：获取该包的 13 位 Base36 ID，调用数据库大事务批量擦除 `metadata` 实体及关联的 `category_items` 数据，同时触发原子计数器修正并通知 UI 完全同步刷新。

## 6.2 数据库反向对账与深度清理机制
为了彻底清理“硬盘上文件早就不存在，但数据库里依然占坑”的幽灵脏数据，手动扫描并清理时必须包含**“以数据库为基准，反向检查物理文件是否存在”**的深度清理逻辑。
1. **全库孤儿元数据反向检查**：
   在后台扫描阶段，不仅顺向检索磁盘空目录，还必须查询全局及各挂载盘数据库中 `is_folder = 1 AND path LIKE '%.arc'`（或所有托管的 `.arc` 文件夹记录），以及所有 `metadata` 中的非空记录。对这些记录中的物理路径，检查其在磁盘上是否真实存在。
2. **完全级联清除与防漏删**：
   若该物理路径已在磁盘上被彻底删除（或根本不存在），但在数据库中仍留有记录，则该记录被判定为“幽灵记录”。系统必须无条件级联清除该 `folder_id` 所对应的所有关联表数据（包括 `metadata` 主表、`category_items` 关系表、`system_stats` 统计表、以及内存缓存），防止脏数据残留。
3. **数据库级联清退规范**：
   在 `MetadataManager::removeMetadataBatchSync` 中，除了 `DELETE FROM metadata WHERE folder_id = ?`，必须级联执行 `DELETE FROM category_items WHERE folder_id = ?` 语句，彻底清除关联。
通过顺向空包检查与逆向数据库对账双轨协同，实现全库数据 100% 极致洁净，彻底根治幽灵数据导致侧边栏计数不发生变化的 bug。

# 7. 关于 AI、PSD、EPS 高性能提图规范
## 7.1 AI 提图高性能渐进分段加载与无脏图净化
1. **渐进式分段流式读取机制（Sliding Header Buffering）**：
   在提取 AI 缩略图时，100% 杜绝一次性强行读取 15MB 庞大裸数据的粗糙做法。改为采用首阶段精准读取前 **1MB** 头部缓存，若在前 1MB 中成功检索到官方 `%AI_Thumbnail:` 块或 XML 中的 `<xmpGImg:image>`，则立即终结读取。仅在无法命中且文件总大小确实大于 1MB 的情况下，才二次渐进向后增量追加加载（最多限制读取 6MB），从而使绝大多数小画册 AI 的文件 I/O 损耗在快速滚动切换时直接下降 15 倍。
2. **零容忍废除暴力检索脏图通道**：
   彻底清退直接在内存缓冲区中暴力查找 JPEG (`\xFF\xD8\xFF`) 与 PNG 幻数的通道 5，以阻断外部置入或内嵌无关背景素材导致缩略图被“偷梁换柱”的安全漏洞。AI 的提取只依靠如下三条核心正轨：
   - **正轨 A（画板官方缩略图）**：Illustrator 导出时官方写入的调色板缩略图（%AI_Thumbnail）或 XMP Base64 元数据预览图。
   - **正轨 B（矢量级矢量光栅化）**：Ghostscript / Windows 原生矢量 PDF 渲染引擎，生成绝对准确的第一页矢量预览。
   - **正轨 C（Shell兜底）**：Windows Shell API 缩略图提图接口安全兜底。
通过以上重构，确保多媒体提取层达到极致性能，且预览图 100% 真实纯净。
