# 0. 关于 ArcMeta 开发规则

## 0.1 职责单一
凡是违反职责单一、逻辑不纯的实现，一律视为失败。

## 0.2 双轨隔离
应用分为"SQLite 内存模式"和"磁盘目录模式"两种。两者运行时各自独立，相互不干扰、井水不犯河水，不共享判断逻辑、不共享数据加载路径。

"SQLite 内存模式"这一命名即是强制约束，不是描述性别名：该模式下唯一合法
的数据读取与持久化方式是 SQLite 数据库查询（categories / category_items /
disk_trash / system_stats 等表）。除 SQLite 数据库之外的任何数据来源——
包括但不限于依赖物理路径前缀匹配判定归属、依赖独立元数据侧车文件（如
.scch）、依赖内存缓存全量扫描（forEachCachedItem 等）替代数据库表关联
查询——一律视为对本条"双轨隔离"原则的直接违反，不因其只存在于内存模式
内部（未污染磁盘模式）而获得豁免。

发现此类非法实现，唯一处理方式是物理根除代码分支与相关注释，不允许以
"备用路径""性能优化""历史遗留、暂不处理"等任何理由保留、延期或部分
处理。相关注释中不得残留已废止方案的名称或描述性文字，避免误导后续
任何人或AI误判其仍然有效、可复用。

唯一豁免：对磁盘上真实存在的辅助/侧车文件（如 .scch）本身进行文件类型
识别与过滤（防止其被误当作正常资产显示），属于文件系统客观事实处理，
与本条禁止的"业务数据源选型"无关，允许保留，但相关注释中不得使用可能
被误读为独立架构方案的措辞。

## 0.3 内存模式数据源唯一性铁律

内存模式（托管库/侧边栏分类模式）下，唯一合法的数据读取与持久化方式是
SQLite 数据库（category_items / categories / disk_trash / system_stats
等表）。

除 SQLite 数据库之外的任何数据来源、任何绕开数据库表关联查询、依赖物理
路径前缀匹配、依赖独立元数据侧车文件（如 .scch）、依赖内存缓存全量扫描
（如 MetadataManager::forEachCachedItem 用于枚举分类归属）来判定或加载
分类内容、统计计数、标签归属、加锁状态等任何业务数据的实现方式，一律视
为非法。

非法的定义不区分实现形式，不因命名、包装方式、性能优化理由、历史遗留
理由而获得豁免——不允许以分支形式存在，不允许以"备用路径""兼容模式"
形式保留，不允许以被判断条件跳过但代码本体未删除的方式潜伏，不允许在
注释、文档字符串、变量名、日志输出中以任何形式提及或暗示其曾经存在
（避免误导后续任何人或AI认为该方案仍然有效或可复用）。

发现任何非法实现，处理方式只有一种：彻底根除，物理删除对应代码分支与
相关注释，不评估是否保留，不设"待观察""暂缓处理"状态。此规则不因"性
能优化""架构升级""历史遗留"等任何理由被绕过、延期或另起分支替代。

唯一例外：对磁盘上真实存在的 .scch 等辅助/侧车文件本身进行文件类型过滤
（即识别并排除这类文件、防止其被误当作正常资产显示），属于文件系统层
面的事实处理，与本条禁止的"业务逻辑数据源"无关，允许保留，但相关注释
中禁止使用可能被误读为"架构方案"的措辞，只能作中性描述（如"排除辅助
元数据文件"），不得出现任何暗示这是一套独立数据方案的表述。

任何相关改动、任何涉及内存模式数据读取路径的新增或修改，必须先对照本
条规则逐条核对，不得脱离本条独立处理，不得重新发明与本条不一致的判断
逻辑。

# 1. 关于“我的分类”与“快速访问”的关联

## 1.1 概念与绑定机制
在侧边栏分类树中，“我的分类”（User Category）与“快速访问”（Quick Access / Favorite Group）本质上共享同一套底层的物理分类表 `categories`。
其中，“我的分类”是基于 parentId 继承链构建的树状分层结构。而“快速访问”则是一组扁平、置顶的镜像代理节点容器。

## 1.2 置顶关联数据模型
每个物理分类在底层数据表 `categories` 中都有一个布尔值属性 `pinned`，代表该分类的置顶状态。
在模型构建（CategoryModel）中：
- 渲染正常自定义分类树时：遍历全部类别并挂载。物理分类节点的 `PinnedRole` 绑定其对应的 `pinned` 属性。
- 渲染“快速访问”分组节点时：系统会遍历所有类别。只要分类的 `pinned` 属性为 `true`（或 1），系统就会在此分组节点下创建一个全新的 **镜像代理节点（Mirror Item）**。
- 该镜像代理节点底层绑定相同的物理 `IdRole`（同为 `cat.id`）、`TypeRole` 等属性，实现高强度的关联和逻辑复用。

## 1.3 交互联动生命周期
在 UI 层（CategoryPanel），右键单击某个具体分类时：
- 若未置顶，右键菜单显示 “添加至‘快速访问’”。点击后将对应分类的 `cat.pinned` 改为 `true`，通过 `CategoryRepo::update(cat)` 持久化落盘并刷新模型。
- 若已置顶，右键菜单显示 “从‘快速访问’中移除”。点击后将对应分类的 `cat.pinned` 改为 `false`，通过 `CategoryRepo::update(cat)` 持久化落盘并刷新模型。
- 不管是从正常自定义树还是置顶列表中点击同一 ID 的节点，两边最终都分发相同的 ID 给逻辑处理模块，保证无缝穿透、完全联动。
