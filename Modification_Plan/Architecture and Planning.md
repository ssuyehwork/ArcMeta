# ArcMeta 核心架构与规划总账 —— Architecture and Planning.md

> 本文档是 ArcMeta 全项目唯一的、合一的顶层架构设计、功能绑定与 UI/视口板块划分规则总账。
> 全应用的分析与设计工作必须强制对齐并无条件遵守本文档所归档的各项规则，禁止 any 形式的另起炉灶与冲突逻辑。

---

## 区块一：顶层架构原则

### 1.1 职责单一原则 (Single Responsibility Principle) 与视图极简
应用中的任何视图类（包括 `ContentPanel`, `CategoryPanel` 等）必须严格解耦，仅承担“界面组件布局管理”、“视图高效率像素渲染与展示”、“用户交互输入捕获与多态信号分发”职责，严禁任何形式的持久层事务、物理磁盘 I/O 阻塞、文件监控与加解密计算逻辑下沉。所有物理外包业务必须彻底剥离并托管至独立的 Processor/Service/Controller（如 `DiskIoService`, `CategoryDropProcessor` 等）。

### 1.2 双轨路由物理隔离机制 (Dual-Route Isolation)
全应用运行于以下两种高内聚且相互不干扰的独立双轨机制之中，两者不共享判断逻辑，数据流与读取路径绝对物理隔离：
* **SQLite 内存模式 (Library 模式 / 镜像加速态)**：数据由 SQLite 数据库中心表驱动。
* **磁盘目录模式 (DiskNav 模式 / 实时 I/O 驱动)**：由真实物理磁盘目录实时扫描对账驱动。
* **溢流与倒灌拦截**：在磁盘导航模式下产生的任何设色、加星、标签、备注等写操作，100% 绝对禁绝写入 SQLite 数据库（零溢流、零倒灌）。必须独占调用离散元数据缓存类 `AmMetaJson` 并写入对应盘符下的 `.ArcMeta.json` 或 `ArcMeta.cache/路径Hash.json` 中。
* **双轨数据来源统一判别**：全应用统一复用并公开 `m_contentPanel->isMirrorSource()` 接口。返回 `true` 代表内容来源于侧边栏逻辑分类模式；返回 `false` 代表来源于目录导航模式。

### 1.3 核心事件方案命名法与历史铁证规范
* **命名规范**：方案文件彻底废止 `Modification_Plan-N.md` 数字命名，必须改用具名、可读性极强的 `核心英文功能事件名.md` 命名。
* **只读不可变升级机制**：已创建的核心事件方案文件永久作为只读历史铁证保留。若方案在后续有任何补充、修改或升级讨论，严禁在原文件上做任何直接更改，必须以文件名后缀递增版本（如 `sort-1.md`、`sort-2.md`）的方式新建，以完美追溯每一次技术迭代。

## 区块二：核心功能与绑定规则

### 2.1 “我的分类”与“快速访问”联动规则
* **共享底层模型**：两树共享同一套底层物理分类表 `categories`，通过 ID 进行高度耦合与完全穿透绑定。
* **置顶状态 (pinned) 关联**：自定义分类树挂载全部类别；置顶列表则动态过滤并遍历仅 `pinned == true` 的分类项，为其建立镜像代理节点 (Mirror Item)。右键点击“添加至/从快速访问移除”时，通过 `CategoryRepo::update` 修改并持久化 `pinned` 属性，并强制刷新模型以实现高强度联动。

### 2.2 分类数据加载与辅助过滤规范
* **数据库绝对主导原则**：在逻辑分类模式（Library 模式）下加载分类内容、条数统计或对账时，100% 仅允许通过中心化的 SQLite 关联表 `category_items` 直接读取，严禁采用前缀模糊物理匹配内存全量扫描（`forEachCachedItem`）的方法进行枚举。
* **辅助文件过滤拦截**：物理盘上存在的 `.scch` / `metadata.scch` 缓存文件在分类与文件列表检索的第一源头必须被强制过滤，严禁将其当作正常资产在界面加载。

### 2.3 调试性日志物理删除与生产异常升格
* **零调试日志残留**：开发调试阶段用于追踪进度、提示进入函数的非异常、无排障和运维价值的 `qDebug` / `qInfo` 输出行，必须物理删除，严禁注释残留或用条件宏包裹。
* **生产故障升格保留**：对于可能发生磁盘 I/O 失败、SQL prepare 编译失败等有极大运维排障价值的严重分支日志，必须升格为 `qWarning` 或 `qCritical` 予以保留。

### 2.4 万级拖拽归类性能规则
* **发起端 I/O 阻塞消除**：拖拽发起时 (`startDrag`)，100% 禁绝对可见项进行 `QFileInfo::exists` 等同步磁盘 I/O 判定。
* **悬停端 O(1) 过滤**：拖拽悬停期间 (`dragEnterEvent`/`dragMoveEvent`)，严禁执行全文本序列化，必须使用 MIME 字符串检测 `hasFormat("text/uri-list")` 瞬间判定放行。
* **后台大事务异步归类 (SRP)**：数万级大批量拖入时，严禁主线程阻塞循环。必须由专门的后台业务处理器 `CategoryDropProcessor` 将归属转换及数据库批量写入托管给后台线程，并强制开启显式大事务。

### 2.5 高级批量创建文件夹与文件规范 (BatchCreate)
* **规则管道构造器**：高级批量创建功能 (`BatchCreateDialog`) 与批量重命名对齐，支持增删自定义规则（Text 固定文本、Sequence 序列数字、Date 日期格式、OriginalName 占位）。根据配置的规则与数量 $K$，管道式遍历计算出目标名称，并在物理磁盘上进行空白写入。
* **起始序列数自动递增自愈**：当包含 Sequence 序列数字规则的批量创建执行成功后，系统必须将序列规则的 `start` 起始值自动递增累加本次创建的数量 $K$，并同步写回配置文件落盘保存，以便下一次打开时自适应递进，实现零阻碍交互。
* **自动自动保存防抖**：交互面板修改类型、数量、后缀、规则等任何行为，统一触发 300ms 自动保存防抖，防丢配置落盘自愈。
* **安全防重名覆盖机制**：不论创建文件还是文件夹，在物理写入前必须进行 QDir/QFile 存在性校验，若重名则自动追加 `(1)`, `(2)` 递增防重名后缀。
* **后缀名点号自动防呆**：对于文件类型，无论用户在后缀配置框中输入 `txt` 还是 `.txt`，系统在读取、持久化保存和执行时统一过滤点号，自动拼接为规范的带有前导点号的后缀（如 `.txt`），防止由于用户输入不合规导致创建失败。

### 2.6 操作快照与 UndoToastOverlay 撤销回滚
* **状态快照抽象 (Snapshot Engine)**：重命名、删除、分类移动等核心状态变更操作前，必须通过 `OperationSnapshotManager` 对资产原路径、标签、收藏状态进行统一快照打包。
* **一键 Snackbar 撤销桥接**：执行成功后，一律拉起 `UndoToastOverlay` 浮窗，并直接将撤销动作绑定到快照对象的 `restore()` 闭包中，实现原子化一键原路回滚。

### 2.7 磁盘模式双向 Persistency 与 MetaPanel 编辑隔离
* **磁盘元数据双向对称加载**：磁盘模式（DiskNav）下，元数据写入时通过 `AmMetaJson` 精准更新至同目录下的隐藏 `.ArcMeta.json`；读取时由 `DiskScanService` 扫描时显式调用 `AmMetaJson::load()`，将其中的相对文件名恢复为规范化物理绝对路径注入快照 `m_snapshot`，形成对等闭环。
* **MetaPanel 编辑冲刷隔离**：当详情编辑器获得键盘焦点或正在被用户输入时，设置 `m_isEditing` 编辑状态锁，绝对禁绝因界面选择改变或后台异步刷新对编辑框内容进行冲刷覆盖。

### 2.8 批量排重决策与全部应用决策链
* **排重对比双卡片**：拖入或导入冲突时拉起 `DuplicateConflictDialog` 排重对话框（标题格式：`重复添加提示 (N)`），呈现“已存在”与“新的文件”双卡片对比。
* **“全部应用 (N)”批量决策**：提供 `[ ] 全部应用 (N)` 的批量勾选框，一旦用户勾选并提交策略（保留两者/使用已存在），直接全自动批量应用至后继全部 $N-1$ 项冲突，取消频繁弹窗。

### 2.9 极速判重与文件 SHA256 缓存落盘
* **三级递进判重原理**：判重处理依次遵循“体积 $O(1)$ 过滤” -> “快速采样 Hash（抽取头尾各 4KB）” -> “全量 SHA256 比对”的递进判重设计。
* **全量哈希 O(1) 内存自愈**：当因发生碰撞触发全量 SHA256 计算后，必须立即通过 `setSha256` 写入数据库或落盘持久化，保证下一次判重比对时直接通过内存快照 $O(1)$ 读取，彻底解决大文件假死。

### 2.10 UI 物理排序稳定保底规范
* **置顶与文件夹恒常置顶**：文件夹和置顶项在升序与降序下永远稳居列表最前列，绝对剔除 `sortOrder` 降序反转的影响。
* **Tie-breaker 平局决胜保底**：当两个资产在对应排序维度（扩展名、大小、尺寸面积、评分等）的值相等时，100% 追加以 `localeAwareCompare` 对比 `filename`（文件名）作为平局保底决胜，尺寸面积排序在 W=H=0 时同样采用此平局决胜，杜绝界面列表随机抖动。

### 2.11 列表视图中文化列标题绑定
列表视图绑定的数据模型（如 `LibraryAssetModel` 和 `DiskItemModel`）必须显式重写 `headerData`。在水平、DisplayRole 下根据 section 绑定返回对应的纯中文字符串：`0`->`"名称"`, `1`->`"状态"`, `2`->`"评分"`, `3`->`"尺寸"`, `4`->`"类型"`, `5`->`"大小"`, `6`->`"修改日期"`。

### 2.12 “添加日期”排序选项数据源限制与严格弱序 (SWO)
* **添加日期选项动态屏蔽**：排序项“添加日期”属于内存专属。在右键或排序菜单构建时通过 `isMirrorSource()`进行硬隔离，若为磁盘模式则强制屏蔽该选项。在排序逻辑中，若磁盘模式被设置此排序，物理强制退化退守为按名称（SortByName）进行比较。
* **分组弱序安全**：分组项（如垃圾箱、Library等）在进行 `FilterProxyModel::lessThan` 分组比较时必须遵循严密的单向优先级排序弱序（SWO），严禁在比较分支中返回双向 true，彻底排除 C++ STL 排序越界崩溃隐患。

### 2.13 全树自定义文件夹总数统计规范
* **全树递归/全量统一计数**：分类树中自定义分类文件夹旁显示的数目（如“文件夹 (N)”）必须 100% 反映所有自定义分类文件夹的全树总和，而并非仅反映第一级顶级节点数量。
* **双向对等更新原则**：
  - 在初始重绘加载时 (`refresh()`)：必须全量累加所有 `kind != CategoryKind::SystemLibrary` 的自定义分类项目作为显示计数。
  - 在接收到数据变动动态更新时 (`updateStatistics()`)：由于节点可能呈多级深层嵌套挂载，计算 `CAT_GROUP_SYS_ID` 下辖自定义项目时必须通过树结构全量递归遍历子孙节点计算，或重新使用一致的全局总计逻辑，严防由于仅读取第一级 `rowCount()` 导致嵌套层级计数缩水、数据不一致的问题。

### 2.14 自定义分类文件夹默认设色物理规范
* **恒定默认色**：系统内置以及用户创建的自定义文件夹分类的默认回退色只能为标准深灰色 **`#555555`**。
* **零脑补恢复**：绝不使用明亮黄色 `#FDB70A` 作为自定义分类默认色。全应用所有产生默认分类颜色的生成位置（如 `getDefaultCategoryColor()`）以及视图渲染器的兜底回退色（如 `CategoryDelegate::paint`）必须 100% 物理保持标准深灰色 `#555555`。

### 2.15 行内编辑新建逻辑子分类联动规范
* **双轨模式分流对齐**：
  - 在磁盘目录导航模式（DiskNav）下：新建文件夹动作仍直接在物理磁盘上通过文件系统创建物理目录。
  - 在受控托管库模式（UserCategory）下：新建文件夹动作自动转化为在 SQLite 数据库中创建指向当前分类的“逻辑子分类（Sub-category）”节点，而不在磁盘上生成冗余物理空目录.
* **一键行内编辑跨域联动**：为了提供极速流畅的用户体验，内容面板（ContentPanel）必须向外发射 `requestCreateSubCategory` 信号；主窗口（MainWindow）绑定信号后，驱动侧边栏分类面板（CategoryPanel）自动定位展开至该父类、自动创建并立即拉起该子类新节点的行内编辑状态，实现零摩擦交互。

### 2.16 侧边栏分类树多维联合多选检索规范
* **多选原子化信号转发**：分类面板（CategoryPanel）在多选激活时，必须将多选信号重构为具名的、以 QList<int> 列表 and QStringList 列表承载的联合多选信号 `categoriesSelected`。
* **无锁高性能多维联合数据查询**：
  - 核心多选加载由内容加载服务（CategoryLoadService）实现，重构为支持 `QList<int>` 的 `loadCategoryItems` 多选联合重载函数。
  - 检索底层直接无缝利用 `CategoryRepo::getItemsInCategories` 进行中心化、去重的 SQLite 大大提升高并发检索效率，消除任何主线程阻塞及 CPU 重复计算开销。
* **多选路由协议自愈对齐**：
  - MainWindow 路由导航体系支持多值逗号分割的多选协议，格式为：`category://id1,id2,id3?name=已选择 N 个分类`。
  - 支持前进、后退（Navigation History）对多选分类状态的无缝重现。
* **多选状态下的右键菜单隔离回退与高强度级联删除**：
  - **右键多选防重置保护**：当多选状态处于激活态，且右键点击了“已选中的项”时，系统强制禁止调用 `setCurrentIndex` 进行无条件选中状态清空；只有当右键点击了“未选中的项”时才执行常规单选切换，从而保全批量右键操作。
  - **多选模型级联对账删除**：批量删除收集时，系统必须首先将代理模型（Proxy Index）在第一时序完全转换为源模型索引（Source Index），再递归累加下辖的所有子孙自定义分类。严禁直接将 Proxy Index 喂给 Source Model 执行 rowCount()，彻底自愈级联失效缺陷。
  - 单项编辑操作（新建子类、密码设置、重命名）则物理隔离、安全回退到指针所在的单点 currentIndex，绝对杜绝多维状态污染。

### 2.17 受控托管库导入行为统一复制规范
* **默认安全复制准则**：所有大资产导入到资源托管库的行为，无论源文件路径与目标路径是否在“同一个磁盘分区”，默认 100% 绝对执行“安全复制 (QFile::copy)”，而不再是隐式 rename（剪切），确保绝对保护用户原本的物理原始资产不丢失。
* **显式参数控制隔离 (allowMove)**：
  - 在 `AssetImporter` 类所有相关导入方法（含 `importSingleFile` 及 `importDirectoryRecursive` 递归）中，增设显式调用控制标志 `allowMove`，且默认值恒常为 `false`（即默认复制）。
  - **唯一允许剪切场景（自动监控导入）**：只有由文件系统在后台发现的“自动监控目录检测导入 (CoreController::watch)”与“首置自定义监控同步导入 (showNewAutoImportDialog)”两个自动后台范畴，且同盘时才显式传入 `allowMove = true` 触发 QFile::rename。用户主动触发的拖拽、剪切粘贴一律强制使用复制，彻底消除因分区一致导致外部源文件被“剪切”走的情况。
* **跨库迁移行为安全复制化**：在进行跨盘托管库资产转移（`MetadataManager::migrateCapsuleToLibrary`）时，同样将对容器胶囊目录的搬移参数改为 `isMove = false`（复制）。

### 2.18 托管库同库与跨库拖拽归类防重判定规范
* **物理路径 100% 预规范化对齐**：为了解决拖拽输入物理路径 `srcPath` 与数据库存储的目标库路径 `targetLibraryPath` 在运行时因斜杠方向差异（`/` 与 `\`）或大小写不匹配导致的判定失效，在进行同库/跨库判定前，必须将两者的路径完全转换并对齐至经过 `MetadataManager::normalizePath()` 的标准化物理绝对路径。
* **同库 0 毫秒静默归类**：当判定拖拽源路径属于目标托管库内部时（即 `isCrossLibrary` 判定为 `false`），必须无条件进入物理库内静默分类关联分支，直接批量写入 `category_items` 数据，严禁触发任何新 ID 生成、胶囊重制、文件系统复制以及任何查重机制（`DuplicateConflictDialog`）弹窗。

## 区块三：UI视口板块划分与数据联动规范

### 3.1 五大核心业务面板划分与折叠边界
全应用视口统一划分为以下 5 大核心主业务面板板块，并严禁打破板块分工边界或胡乱跨域侵入：
1. **分类面板 (CategoryPanel) — [ 占位比例: 230 ]**：逻辑分类树渲染器。管理“我的分类”及“快速访问”列表。
2. **导航面板 (NavPanel) — [ 占位比例: 230 ]**：物理磁盘快捷入口。负责物理盘符及快捷路径收藏夹的管理与联动。
3. **内容面板 (ContentPanel) — [ 占位比例: 600 ]**：中心主数据渲染区。提供 Grid, List, Justified 视图的毫秒级重绘展示与双轨物理/逻辑操作分发。
4. **筛选面板 (FilterPanel) — [ 占位比例: 230 ]**：多维条件过滤器。仅操控 `CategoryFilterProxyModel` 进行本地无锁过滤，绝不重新拉起 SQLite 数据层。
5. **元数据面板 (MetaPanel) — [ 占位比例: 230 ]**：资产属性详情编辑器。利用 `selectionChanged` 从内存 Model Role 中即时零延迟同步属性并提供写入。

### 3.2 分类面板节点严格物理层级与“未分类”桶自愈规则
#### 3.2.1 自上而下挂载层级
1. **系统逻辑桶组**：
   - 全部数据：`sysId = -1`，类型标识 `all`。**核心定义**：包含当前托管库中所有分类（未分类、托管库根分类、用户自定义分类等）里的全部有效数据；**唯一排他例外**：绝对排除“回收站”中的数据（即 `isTrash == true` 的被废弃数据绝对不计入全部数据）。
   - 未分类：`sysId = -2`，类型标识 `uncategorized`。（具体逻辑遵循下述 3.2.2 规则）
   - 未标签：`sysId = -3`，类型标识 `untagged`。
   - 最近访问：`sysId = -6`，类型标识 `recently_visited`。
   - 标签管理：`sysId = -7`，类型标识 `tags`。单击后物理切断主视口，专项独占切换至全局标签管理大屏。
   - 回收站：`sysId = -8`，类型标识 `trash`。专职展现及一键清空/恢复被删除资产，不接受外部拖入或粘贴。
2. **物理托管库根分类**：
   - 挂载标准：自动探测物理盘符，自愈生成 `parentId == 0` 且名称匹配 `ArcMeta.Library_` 前缀的根分类项。
   - **非分类语义（纯记账归属拦截）**：其仅作为物理托管筛选入口，在计算“未分类（uncategorized）”统计或对账时，必须使用排他断言进行拦截（例如 `NOT IN` 指向托管根分类），绝对不准在任何地方将物理库根分类误当作“已分类”标志。
3. **“快速访问”镜像置顶分组节点**：zap_filled 黄标置顶列表。
4. **“分类”自定义树分组节点**：折叠自定义分类层级。

#### 3.2.2 “未分类”业务语义与回收站强自愈规则
* **核心业务定义**：未分类 = 该资产在 `category_items` 表中，不存在任何指向“用户手动/自动创建的分类”（`category_id > 0`）且排除了托管根分类（`parent_id == 0 AND name LIKE 'ArcMeta.Library_%'`）的关联记录。
* **回收站流动自愈行为**：
  1. **入站**：当资产进入回收站（`moveToTrashBatch`），第一时序必须在 `category_items` 表中物理删除该资产的所有分类关联记录（包含托管库根分类关联），然后插入 `category_id = TRASH_CATEGORY_ID` 的记录。
  2. **出站恢复（直接还原至未分类）**：资产从回收站恢复时（`restoreFromTrashBatch`），原有历史分类关联全部不予保留、彻底清空，**直接统一还原至“未分类”**。系统显式将资产划归为“未分类”并同步原子计数器 `s_uncategorizedCount` 执行增量累加，确保零漏记。

#### 3.2.3 “回收站”分类属性定义与四类核心脱离准则
* **核心准则**：只要一个文件/资产被移入到回收站，它在**“全部数据”、“未分类”、“托管库”以及“自定义分类”这 4 个地方的计数必须立刻扣减/彻底清零（脱离关联）**。
* **具体表现**：以用户反馈的回收站数据为例，当这 5 个文件进入回收站后：
  - **属于回收站**：`回收站` 显示 **(5)** 选项。
  - **必须脱离（计数扣减）**：
    - `全部数据` 应该扣减这 5 个，显示 **(0)**；
    - `未分类` 应该扣减这 5 个，显示 **(0)**；
    - `arcmeta.library_z`（托管库）应该扣减这 5 个，显示 **(0)**；
    - 任何属于这些文件的`自定义分类`也应该扣减这 5 个。

### 3.3 内容面板 (ContentPanel) 交互与右键菜单规范

#### 3.3.1 右键菜单 — “永久删除”逻辑架构规范

##### A. 内存模式下：
* **核心准则**：在内存模式（托管库）下，当用户选中项目并执行“永久删除”（Delete Permanently）时，系统必须 100% 执行**物理胶囊 + 数据库元数据 + 内存快照**的三重彻底根除，严禁产生任何遗留垃圾或“幽灵记录”。
* **具体擦除规范**：
  1. **物理层级根除**：递归销毁受控 `.arc` 胶囊文件夹内部的原始素材文件（如 `abc.png`）和缩略图（`abc_thumbnail.png`），并彻底销毁 `.arc` 胶囊文件夹本身。
  2. **数据库层级根除**：从 SQLite `metadata` 主表彻底删掉对应元数据条目，级联清除 `category_items` 分类关联表及 `system_stats` 进度表中的残留记录。
  3. **内存与 UI 状态同步**：从内存快照 `m_snapshot` 中擦除该项，更新原子计数器，并发射全量刷新信号驱动侧边栏计数即时扣减归零。

##### B. 磁盘目录模式下：
> *（注：磁盘目录模式下的永久删除逻辑架构尚未进行专题探讨与定义，暂时留空。）*

### 3.4 UI 交互对齐与偏好规范

#### 3.4.1 输入框一键清除按钮
所有可编辑的输入框一键清除功能，一律且仅允许采用 Qt 原生的 `setClearButtonEnabled(true)`。禁止通过 `addAction`、手动重写 Paint事件或自定义 `QPushButton` 模拟。

#### 3.4.2 窗口无损置顶
窗口置顶状态一律且仅允许使用 Win32 原生 `SetWindowPos`（传入 `HWND_TOPMOST` 或 `HWND_NOTOPMOST`），并配合 `SWP_NOSENDCHANGING` 标志位实现，防止由于 Qt 自带 Hint 导致窗口物理销毁、句柄重建及状态丢失。

#### 3.4.3 标题栏悬停与按下色值
* 默认状态：透明
* Hover (悬停) 状态：`#3E3E42`（系统常量 `Style::HoverBackground`）
* Pressed (按下) 状态：`#4E4E52`（系统常量 `Style::PressedBackground`）
* 严禁手写或在样式表中混入带有半透明 `rgba` 色彩的蒙版。
* **特殊按钮**：全应用的关闭按钮（Close Button）高度视觉统一，其背景颜色在任何时候（默认、悬停）均恒常为 `ErrorRed` (#e81123) 亮色高亮，按下状态切换为 `#A50000`。

#### 3.4.4 撤销提示浮窗 (UndoToastOverlay) 专用居中与交互限制
* **物理位置定位**：在主窗口加载时，`UndoToastOverlay` 浮窗必须固定在父窗口顶边缘向下偏移 50 像素（即 `parentGlobal.y() + 50`）且水平居中对齐的位置，保持极致的视觉焦点统一。
* **业务组件限定**：在进行“批量重命名”或需要撤销/操作完成提示的所有用户反馈交互中，100% 绝对禁绝使用 `ToolTipOverlay`（常规悬浮），必须统一改用 `UndoToastOverlay` 提示。
* **自动刷新与数据一致性**：当高级“批量创建项目...”在磁盘模式空白右键处被触发成功执行后，当前视图必须立即执行自动刷新以在 Model 第一时序恢复最新数据并呈平滑加载，杜绝延迟闪烁。

### 3.5 侧边栏自定义分类一等公民扁平化与隐藏控制按钮规范
* **自定义分类一等公民绝对平铺**：用户自定义分类在树视图（`m_categoryTree`）中作为顶级节点，其左侧视觉上不得产生额外的非必要缩进。为了与系统逻辑分类完美对齐，移除所有阻碍视觉统一的层级缩进和假象父容器。
* **精美按钮视觉实体（文件夹控制按钮）**：`m_btnFolderGroup` 作为隐藏或显示自定义文件夹的专用控制按钮，必须具备清晰、现代、高度吻合桌面专业 UI 质感的按钮视觉特征。
  - **背景色**：默认透明，悬浮（Hover）时切换为优雅的半透明深灰背景色 `#2D2D30`，并带有圆角半径 4px，按下时背景色切换为 `#3E3E40`。
  - **内边距与间距**：左侧预留 15px 内边距与“系统逻辑桶”及“快速访问”完美视觉对齐。
  - **状态双态箭头**：点击一键切换展开 (`▼`) / 收起 (`▶`) 指示图标，右侧随动高亮显示当前自定义分类文件夹的总数计数器。
