## 一、 已彻底解决并转正的“打补丁”历史记录

以下点位历史中是典型的“临时补丁或脏逻辑”，但在前期的物理隔离与 SSOT 重构中已经被**升级为系统级整体设计**，目前标记 `🚨` 是作为高内聚物理隔离屏障：

### 1. 磁盘导航模式与托管模式数据交叉溢流
* **对应文件**：`src/ui/ContentPanel.cpp`
* **历史病灶**：此前磁盘导航模式（DiskNav）会错误地回调并触发托管库的 `syncAfterMove` 或向 SQLite 进行写操作。
* **重构现状**：已被彻底物理隔离（标记为 `[双轨不隔离违规点-5 物理隔离修复]` 等）。磁盘模式仅进行纯粹文件 I/O 与离散 JSON 缓存读写，完全不溢流、不倒灌至 SQLite，实现了物理级双轨隔离。

### 2. 探针盘符探测硬编码与幽灵分类隐患
* **对应文件**：`src/util/AssetImporter.cpp`
* **历史病灶**：
  - 探针盘符探测在历史版本中临时硬编码为了固定的 `D:/`。
  - 当导入时遇到分类父 ID 异常（如 `parentCatId < 0`），数据会留在内存却无法在侧边栏渲染，造成“幽灵隐形分类”。
* **重构现状**：
  - 盘符探测升级为自适应的探针探测运行盘符，废除了硬编码补丁。
  - 安全下限防护逻辑会将 `parentCatId < 0` 的情况一律自动修正重定向为 0（顶级根分类），消灭了幽灵隐形分类。

### 3. 主线程 5 次连续磁盘 I/O 阻塞造成的假死
* **对应文件**：`src/ui/MainWindow.cpp`
* **历史病灶**：每次选中列表资产时，主线程在 `selectionChanged` 里会高频调用 `QFileInfo::exists()`、`isDir()`，造成极长的主线程 I/O 停顿。
* **重构现状**：已彻底重构，直接从 Model 已有缓存拿到数据，用纯内存字符串计算父路径，单击响应速度提高至 0 毫秒，用优雅的缓存机制替代了旧时的卡顿和抢锁补丁。
